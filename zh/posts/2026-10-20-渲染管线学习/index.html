渲染管线概念：从模型数据到屏幕像素#

适用对象：刚开始学习实时图形学与 Unity Shader 的读者

本章路线#

渲染流程看起来像一条直线，但完整的一帧通常由许多相互依赖的绘制步骤组成。理解时可以同时看两张图：第一张解释一个物体如何被光栅化；第二张解释阴影、深度、屏幕空间效果和后处理怎样组成一帧。

坐标变换：顶点为什么要经过好几种空间？#

网格顶点通常用模型自己的局部坐标保存。为了投影到屏幕，GPU 会依次使用模型矩阵、相机观察矩阵和投影矩阵。

设 p_local 是模型局部空间中的顶点齐次坐标，M 是模型到世界空间的矩阵，V 是世界空间到相机观察空间的矩阵，P 是观察空间到裁剪空间的投影矩阵，则：

p_clip = P · V · M · p_local

这里的点积表示矩阵乘法；p_clip 是裁剪空间坐标。Vertex Shader 通常负责至少把位置变换到裁剪空间。投影除法和视口变换之后，位置才映射到屏幕坐标。uv（纹理坐标）、法线、颜色等数据则随顶点一起输出，并在三角形内部插值后交给 Fragment Shader。

片元不一定等于最终屏幕像素。 一个三角形可能在同一像素上产生覆盖片元；深度测试、裁剪、抗锯齿和多重采样会影响最终是否写入屏幕颜色。

两个常见着色阶段#

  • Vertex Shader（顶点着色器）：每个顶点执行一次。常见工作是空间变换，也可以做简单顶点动画或位移。它输出顶点位置和要插值到片元阶段的数据。
  • Fragment Shader（片元着色器）：对覆盖区域产生的片元执行。常见工作是采样纹理、组合颜色、准备法线与材质属性，或计算最终颜色。

Shader 是管线中执行计算的程序；它不等于渲染管线本身。渲染管线还负责筛选对象、安排 Pass、建立缓冲区、选择状态并把阶段连接起来。

Shader 编程入门通常集中在 Vertex Shader 与 Fragment Shader，但它们只是整条渲染流程中由用户编写或配置的一部分。可见性筛选、Pass 调度、缓冲区生成、阴影数据、混合和后处理也都会影响最终画面。因此，先理解每一步的输入、输出和职责，再深入写 Shader，会更容易建立整体认识。

在前向渲染中，Lit Shader 往往会在片元阶段结合表面材质、灯光和阴影数据计算受光颜色；延迟渲染则可能先把表面信息写入 G-buffer，再由后续光照 Pass 计算光照。因而，“Fragment Shader 只准备基础颜色，之后总有一个独立默认光照步骤”不是通用规律。光源数据的组织、阴影可见性计算和表面着色可以由不同阶段提供，但最后会在光照结果中结合。

光照和阴影，可以说是渲染模块里最复杂的部分。它们涉及多个 Pass、不同数据来源和多种算法。

Q：现代渲染管线怎样组织光照与阴影的不同方案？#

现代实时渲染不是在一个固定主干末端依次添加“光照模块”和“阴影模块”。渲染器会根据画质、平台和场景，选择多种数据生成方式，再把它们的结果交给表面着色或后续合成。理解时可把“光照从哪里来”“表面是否被遮挡”“用什么算法求结果”分开看。

先区分光照相关概念#

概念含义常见实现或输入容易混淆的点
直接光照光从光源到达表面，中间没有其他表面反弹方向光、点光源、聚光灯；可配实时阴影光照计算与阴影可见性有关，但阴影图的生成通常是单独的绘制工作
间接光照光到达表面前至少经过一次其他表面反射烘焙光照、探针、实时 GI、SSGI、光线追踪 GI全局光照（GI）通常指模拟间接光照的方法，不等于 AO，也不只是环境光颜色
环境光照对天空、环境和大量远处表面贡献的近似表示环境颜色、球谐光照、Light Probe、环境立方体贴图它是光照贡献或其近似输入；采用某种环境光并不表示完整求解了光线反弹
环境光遮蔽（AO）估算周围几何对半球方向环境光的遮挡程度烘焙 AO、SSAO、GTAO、光线追踪 AOAO 是局部可见性近似，不会生成直接光，也不等于完整 GI 或普通投影阴影
阴影判断光源到受光表面的路径是否被物体遮住Shadow Map、Shadow Mask、屏幕空间估算、光线追踪阴影是光照可见性的一部分；它自身通常不负责产生受光颜色
反射表面把环境或其他物体的光反射到观察方向Reflection Probe、SSR、平面反射、光线追踪反射反射属于镜面方向的环境贡献，与漫反射 GI 相关但不是同一项

“环境光照”和“全局光照”不是同义词。环境光照可以用简单颜色或环境探针近似；全局光照方法则尝试表示表面之间的光传递。环境项可以成为间接光照的一个输入，但环境颜色本身并没有逐次追踪场景中的反弹过程。

阴影与间接光照有哪些路线？#

路线主要数据优点代价与限制
Shadow Map 实时阴影从光源视角绘制的深度图适合动态物体；成熟、适用面广需要额外阴影绘制；分辨率、级联、滤波和灯光类型影响性能与伪影
烘焙光照与阴影离线生成的 Lightmap、Shadow Mask 或探针数据运行时成本较低，可保存复杂静态光照动态变化受限；需要烘焙时间、纹理和内存
屏幕空间阴影与接触阴影相机可见的深度、法线和光源方向（具体输入依实现而异）可补充细小接触细节，避免为所有细节都加高精度阴影图看不到画面外或被遮挡几何；受屏幕数据和采样影响
光线追踪阴影场景加速结构、受光点和朝向光源的射线可自然估算可见性与软阴影射线数量、场景更新、硬件和降噪有成本；实时实现通常有采样或距离限制
Lightmap / Light Probe预计算表面光照或空间采样静态场景质量好，运行时读取较便宜动态对象与动态灯光需要额外方案或混合处理
环境贴图 / Reflection Probe预先或实时捕获的环境方向信息计算便宜，适合环境镜面光照近似位置、遮挡和动态几何精度有限
SSGI屏幕空间深度、法线和颜色可补充相机可见区域的漫反射反弹只能利用屏幕上已有信息，容易缺失离屏间接光
光线追踪 GI场景加速结构和多方向的光线查询能处理较复杂的遮挡、反弹与颜色溢出计算量高，常需降采样、限制反弹次数和时域降噪

表中的“成本”不是固定排名。具体开销取决于屏幕分辨率、灯光数量、阴影距离、采样数、场景动态程度和目标硬件。通常会把烘焙、探针、屏幕空间效果、阴影贴图与少量光线追踪组合使用。

在延迟渲染中，表面属性常先写入 G-buffer，再由光照 Pass 读取；在前向渲染中，Lit Shader 往往在绘制表面时就结合灯光和阴影。屏幕空间效果也可能在光照计算前、计算中或之后运行。上图刻意表达数据依赖关系，不规定某个引擎必须采用的精确事件顺序。

混合光线追踪（hybrid rendering）不要求替换整条光栅化管线。 常见做法是继续用光栅化得到主要可见表面，只对反射、阴影、AO 或 GI 发射光线，再把估算结果降噪后合入。光线追踪 API 通常有独立的射线生成、命中与未命中等 Shader 类型；它们不等同于传统 Vertex/Fragment Shader 的后续 Pass。Microsoft DXR 着色阶段；DXR 光线生成 Shader

另一类是以路径追踪作为整帧主要积分方法。它从相机样本发出路径，沿着与场景的交点继续估算光传递，多样本累积后形成画面。路径追踪不是“Fragment Shader 后追加的一种光照效果”，而是生成整帧图像的另一种渲染算法；引擎仍需负责场景数据、材质、相机和输出等工作。

flowchart LR
    P0[相机像素样本] --> P1[生成相机射线]
    P1 --> P2[与场景几何求交]
    P2 --> P3[读取命中材质并抽样光源/反射方向]
    P3 --> P4[继续追踪有限次反弹并累计贡献]
    P4 --> P5[多样本累积]
    P5 --> P6[降噪与色调映射]
    P6 --> P7[输出整帧]

怎样理解效果、成本与适用范围？#

决策优先考虑常见组合思路
大量静态几何和稳定光照预计算结果是否可接受Lightmap、Shadow Mask、Reflection Probe，加少量实时主光
动态角色和动态灯光变化频率与实时性实时灯光与 Shadow Map；间接漫反射可由 Light Probe 或 Probe Volume 补足
局部接触感与角落层次目标是否是环境遮蔽近似AO 作为局部修饰，避免把它当成完整阴影或 GI
屏幕可见的动态反射可否接受视角依赖与缺失SSR 加 Reflection Probe 或天空环境作为缺失区域的回退
高质量动态反射、阴影或间接光平台是否支持、是否能接受采样和降噪成本光栅化主干配合选择性的光线追踪效果
高质量静帧或离线画面是否可以等待样本累积路径追踪与较多样本累积

Q：什么是屏幕空间光照技术？#

“屏幕空间光照”是对一组读取当前相机缓冲数据、在屏幕坐标中估算光照相关贡献的方便统称，不是一个具有唯一算法定义的单独技术。它们通常使用深度、法线，有时也使用颜色、材质粗糙度、运动向量和灯光信息。由于输入来自当前画面，效果的成本通常与屏幕像素和采样数量密切相关。

常见技术各自估算什么？#

技术主要输入估算贡献典型缺失或伪影
SSAO / GTAO深度与法线近处几何对环境光的局部遮挡不计算完整反弹光；半径过大时会产生不真实的整体变暗
屏幕空间接触阴影深度、法线、光源方向已有阴影图较难表现的细小接触遮挡受屏幕可见性和深度精度限制，不是完整的光源阴影
SSGI深度、法线、场景颜色屏幕可见表面的近似漫反射反弹与颜色溢出离屏反弹光、被遮挡物体和复杂多次反弹信息缺失
SSR深度、法线、粗糙度、场景颜色沿反射方向在屏幕深度数据中寻找交点并采样颜色画面外、被遮挡或未写入颜色缓冲的物体无法正常反射

SSAO 对“周围几何挡住环境方向”的估算可以提高接触与角落的层次，但这只是局部遮蔽近似。SSGI 试图从已有屏幕颜色估算一次间接漫反射；SSR 估算镜面方向的反射颜色。它们的输入、输出和物理意义不同，不宜统称为同一种 AO 或 GI。HDRP 13.1.9 的 SSGI 文档明确说明它使用屏幕深度和颜色缓冲估算漫反射反弹；这与 SSAO 和 SSR 的目标不同。HDRP 13.1.9 Screen Space Global Illumination

为什么它们会丢信息？#

屏幕缓冲只保存当前相机已经绘制出来的数据。被墙挡住的物体、相机视野外的物体、没有进入深度或颜色缓冲的透明表面，都不一定能成为屏幕空间算法的查询对象。因此 SSR 可能在屏幕边缘断裂或找不到反射；SSGI 也可能漏掉画面外的反弹光。屏幕空间反射只能反映当前屏幕可见的数据，这也是实际管线常把它和 Reflection Probe、天空环境或光线追踪反射组合的原因。Unreal Engine：反射与屏幕空间反射限制

时域累积可以利用前几帧的信息降低噪点，但相机或物体运动时可能出现拖影、闪烁或历史信息失配；降噪、抖动采样和运动向量能改善观感，也会增加实现与调试复杂度。增加分辨率、屏幕覆盖面积或采样数量也会提升计算成本。

选择屏幕空间效果时，可以依次确认：需要估算哪种贡献？需要深度、法线还是颜色？目标对象是否会进入这些缓冲？缺失画面外信息时用什么回退？效果在哪个管线时机合成？ 这些问题通常比从一个算法名称开始更容易定位实现方式。

Q：Lit、Unlit 与 Forward Rendering 是什么？#

先区分两个维度：Lit / Unlit 描述材质着色是否采用常规表面光照逻辑；Forward / Deferred 描述渲染器如何组织几何绘制与光照计算。 Lit 不是 Forward 的同义词，Unlit 也不代表物体不会参与任何深度、阴影或屏幕空间处理。

概念它回答的问题典型行为
Lit Shader表面怎样响应光？使用表面颜色、法线、粗糙度等材质数据，结合可用光照计算颜色；URP Lit 通常支持直接光、阴影、间接光与镜面环境贡献，具体受材质、Pass 和管线设置影响
Unlit Shader是否运行常规表面光照模型？默认直接输出材质或节点计算出的颜色，不因场景灯光方向而改变；仍可能参加深度绘制，也可能由后续效果或专门实现影响
Forward Rendering怎样绘制并计算可见表面的光照？绘制物体表面时就着色；Shader 在该次绘制中读取适用于物体/片元的光源与其他光照数据并计算颜色
Deferred Rendering怎样把表面信息和光照计算分开？先把可见表面属性写入 G-buffer，再由后续光照 Pass 读取这些属性并计算光照

Forward Rendering：绘制表面时计算光照#

在前向渲染中，渲染器选择当前相机可见的物体并安排绘制。物体的 Forward Pass 运行 Vertex Shader、光栅化和 Fragment Shader；Lit Fragment Shader 根据表面数据以及 URP 提供的灯光、阴影和环境数据计算受光颜色。简单理解就是“表面被绘制时完成着色”，而不是先为全屏每个像素保存一套表面属性、再统一算光。

这不表示每个 Fragment Shader 都会自动获得完整 Lit 功能。URP 会剔除、整理当前相机和物体可用的光源，并提供 Shader Library 等接口；Lit Shader 或自定义 Shader 仍需通过相应代码消费这些数据。传统 Forward 路径还会受到每物体附加光源数量等设置约束。在支持 Forward+ 的 URP 版本中，它使用分块/聚类的光源列表改善大量光源场景下的光源访问方式，但仍属于前向着色思路。

    B --> D[Lit Forward Pass]

Lit、Unlit 与 Shader Graph / HLSL 的关系#

Lit 和 Unlit 是着色目标/光照行为；Shader Graph 与 ShaderLab + HLSL 是表达 Shader 的方式。 Shader Graph 可以创建 Lit 或 Unlit Shader；用代码也可以编写 Lit 或 Unlit Shader。

名称它说明什么典型结果
URP Lit使用 URP Lit 光照模型解释表面材质参数进入标准光照计算
URP Unlit默认不运行标准 Lit 直接光照模型图或代码直接输出颜色
Shader Graph用节点图描述并生成 Shader 程序可创建 Lit、Unlit 等目标
ShaderLab + HLSL用文本描述属性、Pass、渲染状态和 GPU 代码可更直接控制 Pass 与计算

URP Lit Graph 中的 Base Color、Normal、Metallic、Smoothness 等是表面描述，之后由 Lit 着色逻辑使用。把自己算出的颜色接到 Lit 的 Base Color，并不会自动绕过后续光照。Unlit 默认把结果作为颜色输出；若想做简单漫反射或卡通光照，可以在 Unlit 中显式编写光照计算。

Shader Graph 的连线表示节点间的计算依赖。Unity 把 Graph 编译成 Shader；GPU 仍在渲染管线安排的阶段执行程序。Custom Function Node 可以加入 HLSL 计算；需要添加 Pass、控制更多输入输出或渲染状态时，通常要写 ShaderLab 与 HLSL。

Q：光照是在 Fragment Shader 里算的吗？Unity 又替我们处理了什么？#

在常见的前向渲染中，Lit Shader 通常在 Fragment Shader（片元着色器）阶段对表面应用光照模型。完整画面还可能组合实时灯光、烘焙间接光、环境光、反射与屏幕空间效果；它们由不同的数据准备步骤或 Pass 提供，不一定全部在同一个 Shader、同一个阶段完成。

设 n 为单位表面法线，l 为指向光源的单位方向，ρ 为表面对漫反射光的反射比例（RGB 颜色），I_L 为光源颜色与强度的乘积。最简单的 Lambert 漫反射可写成：

C_diff = ρ · I_L · max(0, n · l)

n · l 是法线与光方向的点积；表面背向光源时它小于零，因此用 max(0, …) 将贡献设为零。这个公式只说明一个方向光对漫反射的简化贡献，不是 Unity Lit 的完整 PBR 公式。

Q：阴影是屏幕空间效果吗？Shader 和管线各负责什么？#

标准实时 Shadow Map 的深度信息来自光源视角。它不是普通的屏幕空间阴影。

URP 调度阴影绘制并传递阴影数据；投影物体的 Shader 需要能参与 ShadowCaster 绘制，接收者的着色也要采样阴影信息。Lit Shader 通常已经实现这些支持。动态物体启用 Cast Shadows 后可以进入实时阴影绘制；是否实时更新、使用多少张阴影图及成本，要看灯光类型、级联和管线策略。点光源需要覆盖多个方向；方向光可以使用多个级联。

硬阴影与软阴影涉及光源和 URP 的阴影设置、阴影贴图和过滤方式。Volume 后处理可以调整整体曝光、颜色和色调映射，但不会改变光的方向，也不会代替阴影几何计算。

Q：DepthOnly、DepthNormals、ShadowCaster 和 SSAO 各做什么？#

一个物体可以被绘制多次，每次绘制为后续算法提供不同数据。

Pass / 效果主要输入主要输出或用途
DepthOnly网格位置、变换深度缓冲区，用于深度预通道、深度纹理等
DepthNormals网格位置、变换、法线供屏幕效果读取的相机法线数据；同时遵守深度测试
ShadowCaster网格位置、光源视角Shadow Map 中的深度
UniversalForward / UniversalForwardOnly表面数据、灯光和阴影输入前向颜色绘制
SSAO Renderer Feature屏幕空间深度与法线（或从深度重建的法线）局部环境遮蔽值

**SSAO（Screen Space Ambient Occlusion，屏幕空间环境光遮蔽）**利用当前相机可见的深度和表面朝向估算角落、接触处等区域的环境遮蔽。它增强局部层次，不是完整的全局光照，也不是 Shadow Map。使用 Depth Normals 来源时，需要对应的 DepthNormals 数据；选择 Depth 来源时，URP 可由深度重建法线。

常见易错点：DepthNormals 主要提供法线纹理，不应把它简单说成“主颜色 Pass”；DepthOnly 与 DepthNormals 的职责有重叠的深度关系，但不能互相代替所有用途。具体哪些对象参加预通道，取决于 Renderer、材质队列、Pass 标签和该效果的设置。

Q：Render Queue 是什么？它能把材质变透明吗？#

Render Queue 是材质参与绘制的队列分组和顺序。它影响对象何时被选中绘制以及采用哪类排序规则。队列本身不会改变材质 Alpha，也不会自动开启透明混合。

透明效果通常还要结合片元 Alpha、Blend 状态、深度写入（ZWrite）和排序等设置。比如 Blend SrcAlpha OneMinusSrcAlpha 会按 Alpha 混合前景与背景；ZWrite Off 是许多透明表面的常见选择，但也不是透明度的唯一判据。队列与混合状态共同影响结果，因此两者要分别检查。

        C4[场景深度] --> C5[遮挡与合成]
        C3 --> C5
    end
  • 水面通常仍是一个表面。法线可扭曲屏幕背景采样来近似折射；反射可以来自天空、Reflection Probe 或额外相机；深度差可用于岸边颜色和泡沫。若读取场景颜色/深度，就必须有对应纹理和正确的执行时机。
  • 体积云占据空间。常见 Ray Marching（光线步进）做法是求出视线与云体的交段，在其中反复采样密度和光照，再累计颜色与透射率，最后按场景深度合成。
  • 屏幕空间表示算法读取屏幕颜色、深度、法线等缓冲数据；它是一类数据来源/处理空间，不等同于全部光照、阴影或后处理。
  • Volume是用于保存并混合场景效果参数的系统。名字里有 Volume 并不意味着它就是“体积云”或体积雾。

Q：Compute Shader、GPU Instancing、间接绘制与粒子碰撞在哪里？#

这些是相邻但不同的问题：

  • Compute Shader：GPU 上的通用并行计算任务；可以更新大量粒子或筛选实例，不属于标准 Vertex/Fragment 主干。
  • GPU Instancing：把许多相同网格的绘制合并成较少的绘制请求，减少 CPU 提交开销；它不是光照模型。
  • Draw Mesh Indirect：利用 GPU 侧生成的绘制参数提交网格绘制，常和 Compute Shader、实例化配合；具体 API 依 Unity 版本变化。
  • 粒子碰撞：少量需要真实刚体交互时可用 Rigidbody；常规视觉粒子可用 Particle System Collision；大量粒子可研究 VFX Graph 的深度缓冲碰撞，但这只是对可见表面的近似。

Unity 渲染管线：概念如何映射到 Unity#

本章先讲一般关系，再标出与本项目 Unity 2022.1 / URP 13.1.9 相关的版本细节。

Q：Built-in、SRP、URP 和 HDRP 是什么关系？#

Unity 项目需要一套流程把场景变成屏幕图像。Built-in Render Pipeline 是 Unity 传统内置管线；SRP（Scriptable Render Pipeline，可编程渲染管线）是 Unity 提供的可编程框架；URP（Universal Render Pipeline）和 HDRP（High Definition Render Pipeline）是基于 SRP 的两套管线。

  • URP 面向较广的平台和可扩展的性能配置。
  • HDRP 面向较高端硬件与更丰富的高保真渲染功能。
  • Built-in 使用传统管线的着色器接口与资源组织方式。

它们的功能、Shader 接口和 Renderer 配置并不完全相同。一个管线中的 Shader 不能假设换到另一条管线就能原样工作。选择时要看目标平台、画面要求、团队资源和项目阶段；中途换管线通常需要迁移材质与效果。

**版本提示：**功能对比随 Unity 与渲染管线包版本变化。本项目固定 Unity 2022.1.25f1、URP 13.1.9；涉及某个功能是否内置、Renderer 字段名称或 Shader Pass 行为时，以该项目版本为准。

Q：URP 的配置分别在哪里？#

Unity 的渲染配置不是一个单独的“管线开关”。项目设置选择管线 Asset，管线 Asset 再引用一个或多个 Renderer Data；Renderer Data 决定采用哪些渲染步骤和扩展功能；场景对象、相机、灯光、Volume 等向这些步骤提供输入或参数。

URP Asset 可以有多份，例如性能、平衡和高保真配置；质量档可以选择不同 Asset。Renderer 则可以有不同配置并由管线 Asset 或 Camera 选择。改变一个 Asset 的参数可能影响所有引用它的相机与质量档，因此要先确认引用关系。

Q：Renderer Feature 和 Pass 是什么？#

这里有两个相似但不同的“Pass”用法：

  1. ShaderLab Pass 是 Shader 内的一次绘制描述。它可以有自己的顶点/片元程序、LightMode 标签、Blend、深度和剔除状态。
  2. URP render pass 是管线安排的一步工作，例如绘制不透明对象、生成深度/法线，或运行全屏后处理。

LightMode 标签帮助 URP 判断某个 ShaderLab Pass 是否适合当前管线步骤。Renderer Feature 则允许 Renderer 加入某些预构建或自定义的管线步骤，并定义它们的执行时机。一个 Shader 有一个颜色 Pass，不代表它自然就能生成深度、相机法线或阴影贴图。

典型关联：

管线步骤Shader 常见 Pass 标签/数据读写目的
前向不透明绘制UniversalForward 或 UniversalForwardOnly着色并写颜色/深度
深度预通道DepthOnly写深度供遮挡、深度纹理或后续处理使用
法线预通道DepthNormals / DepthNormalsOnly输出供屏幕效果采样的法线数据

实际可执行顺序不是所有项目都固定为同一条线：渲染路径、Renderer Feature 的注入点、相机栈、透明队列和平台能力都可能改变顺序或省略某些 Pass。使用 Unity Frame Debugger 可以观察当前相机实际执行的绘制事件与目标缓冲区。

实际的渲染执行里面是一个图结构,可能要执行多个Render Pass. 每个Render Pass里面又有多个Shader Pass.

Q：Shader Graph 是“参数面板”吗？能否自己写 PBR？#

Shader Graph 是 Shader 的一种可视化编写方式。它根据节点图生成 Shader 程序。图里选择 URP Lit 目标时，常见输出块描述表面属性，例如 Base Color、Normal、Metallic、Smoothness；URP Lit 光照模型使用这些输入来计算着色。图选择 URP Unlit 目标时，默认直接输出颜色，不自动采用标准 Lit 光照。

从简单到更可控有几种做法：

想达到的目标合适的起点还由谁负责
贴图或纯色受标准灯光照亮Lit Graph / URP Lit 材质URP Lit 继续处理光照与支持的阴影等
自定义颜色、法线或金属度，但保留标准光照Lit Graph 节点或 Custom FunctionURP Lit 仍执行标准光照模型

控制 Pass、渲染状态、顶点数据结构或更完整的自定义 BRDFShaderLab + HLSL自己实现并维护需要的管线接口

如果把已计算的最终光照颜色接到 Lit 的 Base Color，URP 仍可能继续对其执行 Lit 着色；如果目标是直接输出自己的最终颜色，一般从 Unlit 目标开始更清楚。Custom Function 可增加 HLSL 计算，但它本身不负责创建新的 Renderer Feature 或 ShaderLab Pass。

Q：动态光、烘焙光、Probe 和阴影怎样进入 Shader？#

通常不需要在材质面板逐个绑定场景灯。管线和 Renderer 按项目设置、场景灯光、对象范围与渲染路径准备可用数据；Lit Shader 使用相应输入。材质主要描述表面。

  • 实时灯光：每帧或按管线策略更新；URP 会按可见范围、灯光数量限制和渲染路径处理主灯与额外灯。
  • Lightmap：提前把部分静态表面光照写入贴图。静态对象运行时采样这些烘焙数据。
  • Light Probe：在空间中存储烘焙的间接光照样本，运行时插值，为动态对象近似间接漫反射。
  • Reflection Probe：从场景某处采集立方体环境图，为反射表面提供环境信息；它不是完整的实时光线追踪。
  • 实时 Shadow Map：URP 组织从光源视角的阴影绘制；Shader 参与写入投影深度并在受光表面查询阴影。

灯光照亮表面的计算和实时阴影贴图生成是两笔不同的成本。增加实时阴影常增加额外的深度绘制；点光源覆盖多个方向，方向光可能采用级联。动态光并不等价于“每盏灯对每个像素做一条光线追踪”。

Q：硬光/软光应该调后处理还是 Shader？#

先调整灯光、材质和阴影，再用 Volume 做画面收尾。

  • 想要阴影边缘锐利或柔和，检查 Light 的阴影类型、URP 阴影支持、贴图分辨率与过滤设置。
  • 想让建筑空间层次更明显，调整主光方向、强度、环境光、材质粗糙度与阴影范围。纯色哑光材质可以先帮助观察几何结构。
  • 想统一整体明暗、色彩和色调映射，使用 Volume 中的曝光、Color Adjustments、Tonemapping 等。
  • 想改变表面对光的数学响应，例如卡通分段明暗、自定义 BRDF，再考虑自定义 Shader。

后处理改变最终图像，不会替代正确的入射光方向、投影几何或材质响应。SSAO 可辅助表现接触处，但不应把它当作主阴影或全局光照。

Q：Volume 是什么？它是不是体积渲染？#

Volume 是用于影响相机效果的场景组件。它引用 Volume Profile 资源；Profile 内保存 Tonemapping、Bloom、Vignette 等 Override 的开关和参数。Global Volume 可影响整个相机范围；Local Volume 可依据体积形状、Layer、Priority 与 Blend 距离影响附近相机区域。

Volume 是“效果参数如何作用于相机”的系统；它不等于云、雾或水这样的体积介质。某些体积雾功能会使用 Volume 参数，但真正的体积效果仍需要相应的渲染实现。另一个关键区分：本项目的 SSAO 是 Renderer Data 中的 Renderer Feature，不在 Volume Profile 内。

Q：效果需要额外 Pass 时，谁来加？#

先确认输入数据是否已经可用，再判断是否需要加新的工作步骤。

  1. 只需当前物体的位置、法线、UV、贴图与灯光：通常改材质 Shader 就够。
  2. 需要场景深度、已绘制的不透明颜色：启用相机对应纹理需求，并确认该纹理的格式与执行时机。
  3. 需要给特殊物体重绘一次、输出自定义缓冲、生成反射相机纹理或做全屏处理：考虑 Renderer Feature/额外 Render Pass，以及负责调度的少量 C#。
  4. 需要许多粒子、实例或网格由 GPU 大规模更新：可研究 Compute Shader、GPU Instancing 与间接绘制；它们解决的是数据并行计算/绘制提交问题，不等同于普通 Fragment Shader。

无需一开始“重写管线”。URP 已提供的深度、颜色、阴影与光照输入可被复用；扩展工作的核心是明确新增数据是什么、何时生成、谁读取、最后如何合成。

材质 Smoothness、Emission 等值作为 Graph 属性或表面参数改变 Lit 表面响应或发光输入

2. Graph_Unlit_Texture.shadergraph：Unlit Graph#

输入 UV 并采样 Base Map，将纹理颜色送至 Unlit 输出。它用于观察最短的“网格 UV → 纹理采样 → 颜色输出”路径。默认不因场景灯光自动改变颜色。若想自己做光照，可在 Graph 中显式加入光照数据与计算。

3. 02_CodeLitTexture.shader：ShaderLab + HLSL Lit#

主 Pass 的输入包含顶点位置、法线、UV、贴图、Base Color、Metallic、Smoothness，以及 URP 提供的光照/阴影输入。顶点阶段变换位置、法线并传递 UV 与世界位置；片元阶段采样纹理、构造 SurfaceData 和 InputData，再调用 URP UniversalFragmentPBR。这个例子是代码编写的 Lit Shader，但 PBR 光照函数仍由 URP 提供。

主 Pass 输出受标准 PBR 光照影响的颜色。另有 DepthOnly 与 DepthNormals Pass，用于深度预处理和需要相机法线数据的效果；它是教学简例，没有实现完整的所有 Shader 功能，例如专用 ShadowCaster 与 Lightmap Meta Pass。

4. 03_CodeUnlitTexture.shader：ShaderLab + HLSL Unlit#

片元阶段采样 Base Map 与 Base Color 后，直接输出颜色；不执行 URP 标准 Lit 光照。它也包含 DepthOnly、DepthNormals 预处理 Pass。与 Lit 例子用同一张 Checker 贴图，可以通过转动/关闭 Directional Light 比较两者：Lit 会响应灯光，Unlit 默认不会。

5. 04_CodeParallaxUnlit.shader：基础视差贴图#

这个例子说明同一 Shader 如何在常规片元着色里增加一种表面纹理处理。

顶点位置、法线、切线、UV、相机方向
            ↓
顶点阶段把观察方向转换到切线空间
            ↓
片元阶段采高度图，并按高度与观察方向偏移 UV
            ↓
使用新 UV 采样颜色图
            ↓
Unlit 颜色输出

材质输入为 Albedo、Height 与 Parallax Scale；输出是偏移后纹理坐标采样得到的颜色。它只改变贴图查找位置，不移动网格顶点、不改变几何轮廓，也不会自动生成匹配的深度或视差阴影。高度图是线性数据，白色代表较高、黑色代表较低。把 Scale 设为 0 可与普通纹理对照。

Q：怎样在 Unity 里对比这些例子？#

  1. 打开 Assets/Scenes/SampleScene.unity，在场景中准备几个 Cube、Plane 或带 UV 的球体。
  2. 从 Assets/RenderingLearning/Materials/ 拖入 M_01_UnlitGraph、M_02_CodeLit、M_03_CodeUnlit，用同一 Checker 贴图比较 Graph/HLSL 与 Lit/Unlit。
  3. 旋转或关闭 Directional Light，观察 Lit 材质明暗变化，和 Unlit 材质作比较。
  4. 将 M_04_CodeParallax 放在有 UV 与切线的网格上，观察斜视角；从很小的 Parallax Scale 开始，随后设为 0。
  5. 从 HighFidelity 切换 Balanced 或 Performant 质量档，对照阴影距离、额外灯与抗锯齿预算等变化。
  6. 在 Renderer Data 中查看 SSAO Feature；在场景 Global Volume 中查看 Volume Profile。改变时分别确认自己改的是管线处理还是相机后处理参数。
